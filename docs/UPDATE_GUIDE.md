# คู่มืออัปเดตโค้ดหลังส่งมอบ (ทาง A)

ใช้เมื่อแก้บั๊กหรือเพิ่มฟีเจอร์ โดยครูแชร์ Sheet ให้ Gmail ผู้พัฒนาเป็นผู้แก้ไขไว้แล้ว

## 1. ฝั่งผู้พัฒนา: แก้และทดสอบในต้นแบบก่อนเสมอ

```bash
npm test
SEED=1 npm run dev  &&  node tests/e2e.cjs
clasp push          # ไปที่ Sheet ต้นแบบ แล้วทดสอบบน Apps Script จริง
git commit ...      # บันทึกเวอร์ชัน
```

## 2. วางโค้ดใหม่ในโปรเจกต์ของครู

**ด้วย clasp:** เปิด Apps Script ของ Sheet ครู → ⚙️ การตั้งค่าโปรเจกต์ → คัดลอก **รหัสสคริปต์** แล้ว

```bash
cp .clasp.json .clasp.template.json
echo '{"scriptId":"<รหัสสคริปต์ของครู>","rootDir":"src"}' > .clasp.json
clasp push
mv .clasp.template.json .clasp.json        # กลับไปชี้ต้นแบบ
```

**หรือด้วยมือ:** เปิด Apps Script ของ Sheet ครู แล้ววางทับเฉพาะไฟล์ที่เปลี่ยน

> การอัปเดตเปลี่ยนแค่โค้ด ข้อมูลในชีตไม่หาย ถ้าเวอร์ชันใหม่เพิ่มคอลัมน์ ระบบจะเติมต่อท้ายชีตให้เองตอนเปิดเว็บ (`ensureColumns_`)
> ห้ามเปลี่ยนชื่อหรือลำดับคอลัมน์เดิม ให้เพิ่มต่อท้าย `COLUMNS` ใน `Config.gs` เท่านั้น
> ก่อนอัปเดตที่เปลี่ยนโครงสร้างข้อมูล ให้ทำสำเนา Sheet ของครูเก็บไว้ (ไฟล์ → ทำสำเนา) หรือดู "ประวัติเวอร์ชัน" ได้ภายหลัง

## 3. ฝั่งครู: กดใช้เวอร์ชันใหม่ (3 คลิก, ลิงก์เดิม)

1. ใน Apps Script กด **ทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้**
2. กดไอคอน ✏️ (แก้ไข)
3. ช่อง "เวอร์ชัน" เลือก **เวอร์ชันใหม่** → กด **ทำให้ใช้งานได้**

ถ้าเวอร์ชันใหม่ขอสิทธิ์เพิ่ม (แก้ `oauthScopes`) ครูจะต้องกดอนุญาตใหม่อีกครั้ง

## 4. ตรวจสอบ

- [ ] ครูเปิดลิงก์เดิม เห็นการเปลี่ยนแปลง (ถ้าไม่เห็นให้รีเฟรช)
- [ ] ดูชีต `ErrorLog` ว่าไม่มีข้อผิดพลาดใหม่
- [ ] ถ้าตกลงกันไว้ ให้ครูถอนสิทธิ์ผู้แก้ไขของผู้พัฒนาหลังอัปเดตเสร็จ

## รหัสข้อผิดพลาดที่พบบ่อย

| รหัส | ความหมาย |
| --- | --- |
| `ERR-NETWORK` | หน้าเว็บติดต่อ Google ไม่ได้ (เน็ตหลุด) |
| `ERR-VISIT-*` | ข้อมูลการบันทึกไม่ครบ/ไม่ถูกต้อง (แสดงข้อความให้ครูแล้ว) |
| `ERR-IMPORT-*` | ไฟล์นำเข้าว่างหรือใหญ่เกิน |
| `ERR-<ชื่อฟังก์ชัน>` | ข้อผิดพลาดที่ไม่คาดคิด → ดูรายละเอียดในชีต `ErrorLog` |
